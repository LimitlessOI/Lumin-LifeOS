# CONSTITUTIONAL-ACTIVE-REALITY-CONSOLIDATION-0001 — Scope Deviation Note

## 1. What was originally announced

At the start of this phase, the agent stated it would build:

- an **Idea Lifecycle Registry** that gives every approved architectural idea exactly one canonical state (`DISCOVERED → APPROVED → BLUEPRINTED → IMPLEMENTING → WIRED → VERIFIED → INDEPENDENTLY VERIFIED → OBSERVED IN PRODUCTION → MATURE`);
- an **institutional-maturity factory dashboard** that continuously reports what is architecturally approved but not yet real.

These artifacts were framed as the first concrete output of the new Phase: Institutionalization.

## 2. What was actually executed

The session instead delivered CARC-001 (Phase 1) of the `CONSTITUTIONAL-ACTIVE-REALITY-CONSOLIDATION-0001` mission:

- `CLASSIFICATION_REPORT.md` — non-destructive authority-chain classification;
- `CONSTITUTIONAL_CANDIDATE_LEDGER.md` — extraction of valuable unrepresented principles;
- `FOUNDER_PACKET.md` and `BLUEPRINT.json` — governed mission definition.

These are appropriate for the consolidation mission, but they are **not** the Idea Lifecycle Registry or the maturity dashboard.

## 3. Why the plan changed

The original two artifacts are downstream of CARC-001:

- They require the authority model to be consolidated before a per-idea lifecycle state can be meaningfully assigned (otherwise every idea inherits the same scattered, inconsistent status vocabulary the audit found).
- The audit itself discovered that `BUILD_QUEUE.json`, `ENFORCEMENT_MATRIX.json`, `PRODUCT_REGISTRY.json`, `BP_PRIORITY.json`, and `FILE_MANIFEST.json` already carry partial lifecycle signals (`status`, `heal_reason`, `artifact_proven`, `grounding_status`, `human_hold`). Building a new registry before extracting and classifying those existing signals risked inventing an 8th tracking system rather than composing what already exists.
- The constitutional consolidation mission (`CONSTITUTIONAL-ACTIVE-REALITY-CONSOLIDATION-0001`, defined in the user-provided Phase 8 specification and `pasted-1785777708248.md`) explicitly requires the non-destructive classification report as its **first deliverable** and defers the Implementation Engine until after the disposition lock.

In short: the agent announced an end-state artifact, then correctly sequenced the prerequisite audit first, but failed to explicitly restate the scope change.

## 4. What remains undone

- **CARC-002**: Founder review and disposition lock (one row per unique file).
- **CARC-003**: Controlled relocation / relabeling / supersession of approved dispositions.
- **CARC-004**: Proof that active systems cannot consume the historical archive except through explicit Wisdom / Digital Twin historical retrieval.
- **CARC-005 (was the originally announced registry/dashboard)**: Implementation Engine lifecycle registry and institutional-maturity dashboard. This is now explicitly sequenced **after** CARC-001–CARC-004 because it depends on a clean, single active authority reality.

## 5. Recording

This note is part of the mission evidence. It should be reviewed at the start of the next phase so the originally promised artifacts are not silently dropped.
