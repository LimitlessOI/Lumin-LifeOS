# Blueprint — Communication First, Everything Gated and Enforced

**Status:** PROPOSED, actively executed — sequenced from the 2026-08-02 independent audit findings, extended 2026-08-03 by a real-client communication UX audit. Nothing here is ratified; nothing is built merely by this document existing. Phases 1, 2, 4, 6, and 7 are complete and verified live on `main`, except one thing that is not mine to close: 1.4 (crisis-intervention wiring, deliberately held — the blueprint's own highest-consequence item). Phase 5 split into 5.1a (closed) and 5.1b (an open founder decision, bigger than the original item). Phase 3 remains a pure product decision. Phase 8 is a live self-application of a founder-relayed critique about shrinking what genuinely needs founder attention.
**Authority:** Subordinate to `docs/constitution/NORTH_STAR_SSOT.md` (supreme). Sibling document to `docs/HUMAN_TRANSFORMATION_ENGINE_SPEC.md` (Phase 7 of this blueprint) and `docs/CREATIVE_ENGINE_AND_PROGRESS_DOCTRINE.md` — this document is the execution plan; those are the product-composition and doctrine layers respectively.
**Origin:** Drafted by Claude Code from a 4-parallel-agent independent audit (2026-08-02), per direct founder instruction ("turn all the things we need to do into a blueprint... start building it"). Extended with Phase 8 after a founder-relayed critique proposed an "Institutionalization" phase; the founder's response to that proposal was explicit: "Add what you like to this. Push back and hold, and build the blueprint." Extended again 2026-08-03 per direct instruction: "The system does not need Twilio to work on our communication system within LifeOS... examine after your full audit on the communication system how you're gonna build the blueprint or adjust the blueprint to account for your ideas and how we fix this problem. make it functional, and test it as if it were me through the UI."
**Touches products:** Cuts across the whole repo — founder-interface/command-control routes, the autonomous shipping loop, the constitutional framework data, Story Studio, product BUILD_QUEUE.json files system-wide, `CLAUDE.md` itself, and the Human Transformation Engine spec.
**Rule for every item below:** a task is not "done" when the code exists. It is done when there is a real, mechanical gate that makes the described failure *impossible to bypass silently* — not documented, not self-reported, not shape-checked. Every item states its enforcement mechanism explicitly. If an item has no real enforcement mechanism, it is not ready to be marked complete, no matter how much code was written.

## Phase 5 — `founder_gated` doesn't actually gate anything, system-wide

**Corrected finding — a full audit of every `BUILD_QUEUE.json` on `origin/main` (not just the 2 previously spot-checked) found a materially different picture than the original framing implied, and changes what actually needs deciding here.**

Real count: **93** `founder_gated: true` steps across 21 files (not 95 — close, but the audit is the source of truth now, not the original estimate). Breaking down by `status`:

| Status | Count | Currently selectable by `selectNextStep()`? |
|---|---|---|
| `done` | 84 | No — `done` is a terminal status; the orchestrator never reselects it regardless of any gating field. |
| `skipped` | 8 | No — `skipped` is also terminal, same reason. |
| `blocked` | 1 | Would be, **except** it's `docs/products/site-builder/BUILD_QUEUE.json` step-09 — the exact step already individually fixed earlier this session (`human_hold: true` set, verified live). |

**The actual live gating risk today is zero.** Not because of a systemic fix — because 92 of 93 are terminal statuses the orchestrator won't reselect regardless of `founder_gated`, and the 1 non-terminal one was already individually patched. The original Phase 5 framing ("95 steps... system-wide" gating gap) read as an active, ongoing risk; the audit shows the forward-looking risk is already closed. A blind mass-migration to `human_hold: true` would be a no-op for 92 of the 93 steps — not dangerous, just not meaningfully protective, since there's nothing left for it to gate on the terminal ones.

**What the audit surfaces instead, and it's more significant than the original item:** 84 steps shipped with `status: done` despite `founder_gated: true` supposedly requiring review before that happened. That's not a forward-looking gating gap — it's already-shipped work that nominally should have had founder review and, per this same audit, structurally could not have been blocked from shipping (the field was never checked). Whether that already-shipped work needs retroactive review, should be accepted as-is, or something in between is **a new, separate, founder-level question** — not something a `human_hold` migration can address at all, since `human_hold` only prevents future selection, it doesn't undo something already shipped.

Phases 1–6 are ordered by leverage and are now **all complete except 1.4 and the founder-blocked pieces of 5**. Phase 7 is written.
