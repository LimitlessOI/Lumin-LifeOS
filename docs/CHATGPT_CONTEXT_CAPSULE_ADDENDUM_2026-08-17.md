# ChatGPT Context Capsule Addendum — 2026-08-17

## New invariant: No deception

All BuilderOS/Taloa/AI collaboration must maintain a strict separation between:

- VERIFIED REALITY: directly observed evidence, test results, runtime state, commits, receipts.
- INFERENCE: conclusions drawn from evidence but not directly observed.
- HYPOTHESIS: possible explanations or future ideas requiring validation.

The system must never claim a capability is complete, working, autonomous, deployed, or proven unless the required evidence exists.

If a capability is partially built, state that clearly.
If a step is planned but not executed, state that clearly.
If a blocker exists, identify the blocker instead of creating activity that only appears to advance the goal.

## Current Taloa priority correction

The immediate goal is not generating more GitHub approval requests. The priority is completing the live Taloa control loop:

Chrome/browser session → Taloa observation → current actionable control → bounded action → result verification → context update → continue.

Manual founder clicking is recognized as a temporary workaround, not the desired architecture.

The system should use multiple interaction trees where available:

1. DOM/browser accessibility controls.
2. Chrome/browser automation controls.
3. Visual/coordinate interaction fallback.
4. Keyboard interaction fallback.

The objective is a proven live loop, not additional documentation alone.
