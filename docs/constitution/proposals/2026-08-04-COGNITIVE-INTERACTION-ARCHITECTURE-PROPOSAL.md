## The core claim, stated plainly

The existing Communication DNA is strong on *what not to do* (no formula, no fake execution, no manipulation) and on *style* (twin-matched tone, anti-formula). It does not have an explicit, first-class step that decides, before any words are chosen, **what kind of conversation this moment actually calls for** — presence, reflection, discovery, guidance, execution, or something else. That decision currently exists, but only as a handful of independently hand-written special cases in `chair-direct-agent.js`'s system prompt (presence/vent turns, tonal distress, factual status queries). This proposal is about making that an explicit, reusable mechanism instead of scattered special cases.

**This is confirmed to already be latent, not foreign, in ratified doctrine:**
- The **Chair Intent Protocol** (`docs/LUMIN_DOCTRINE.md`) already requires "understand before executing" for *command* turns — this generalizes the same discipline to *conversational* turns.
- **"Hard-gate the reasoning, not the behavior"** (`docs/CREATIVE_ENGINE_AND_PROGRESS_DOCTRINE.md` §3) is the same architectural move applied to the Six Laws — this applies it to conversational mode selection.
- **"Ask before assume" / Socratic bias / "a good question beats a clever answer"** is already ratified self-voice (2026-07-03) — "Discovery Before Direction" sharpens this into a mechanism, it doesn't invent it.

**Second-round addition, accepted: shared understanding comes before mode.** The Chair Intent Protocol's existing "understand before executing" step says to ask until intent is clear, but not *what kind* of clarity to look for. One sentence can hide several entirely different underlying conversations — "I'm afraid to quit my job" could be about money, identity, fear, family, timing, or permission, and picking one without checking is still guessing. This is not a new layer above mode-selection; it's the missing content of the *existing* Understand step, sharpened. Folded into A2 below rather than given a separate step number, so the doctrine doesn't grow a parallel "Understand" and a parallel "Shared Understanding" that agents have to reconcile.

**Third-round addition, accepted — the load-bearing find: this whole proposal already has supreme authority, under a different name.** Round 3 named a unifying principle — "the AI may participate in thinking, but ownership of meaning remains with the human" — and called it a new discovery. It is not new: it is **User Sovereignty**, already a HARD RULE in `CLAUDE.md` ("Never manipulate or steer against user goals. No dark patterns"), sitting near the top of this system's entire priority stack. What round 3 correctly noticed is that an already-supreme principle, phrased so far in terms of *action* (don't steer someone's behavior), also governs *cognition* (don't own someone's meaning-making). This proposal doesn't need new authority granted to it — it needs to correctly cite the authority it already has. Everything else in this document is downstream of that one already-ratified rule, not a new invention standing beside it.

## D — Where round 2 overreached, and why it isn't folded in as written

Recorded explicitly rather than smoothed over, because this session's own discipline all day has been to write down disagreement, not average it away:

**"Replace modes with nine cognitive primitives (certainty, ambiguity, emotional intensity, cognitive load, openness, momentum, agency, readiness, trust)."** Not adopted. This doesn't make the underlying problem more tractable — it relabels it with more variables. Each of those nine is at least as hard to actually read from a single message as the mode itself was, and the round-2 argument's own logic admits mode still gets *derived* from them ("if you know those, the mode almost chooses itself") — meaning mode remains the actionable layer either way. What's genuinely useful in this critique, and is kept (as the A2-risk caveat above): mode-selection should be driven by legible signals in the actual conversation, not assumed from a fixed decision tree. That's a real, smaller, more honest version of the same instinct.

**"This is a new layer of AI architecture, a candidate for something more general than LifeOS."** Not adopted as stated. The philosophical territory here — grounding, common ground, mixed-initiative dialogue — isn't new to AI/HCI research; it goes back decades. What's actually uncommon isn't the philosophy, it's building it with real enforcement, real receipts, and a real outcome ledger instead of leaving it as a paper concept — the discipline this whole session has run on, not a new paradigm claim. Overclaiming novelty here would be exactly the kind of unbacked claim the Honesty Standard this system runs on exists to catch.

**Round 3: rename and elevate this out of "Communication" entirely into a domain-general "Collaborative Cognition Architecture," applying the same principles to roadmaps, UI, financial models, lesson plans — anything Lumin generates.** Not adopted, on scope-discipline grounds, not correctness grounds — it may well be right. But it is the same pattern this session has repeatedly found and corrected elsewhere tonight (Priority 4: don't build a Translation Layer for an audience that doesn't exist yet in production; Priority 5: don't build Wisdom before real outcome data exists) — expanding scope before the narrow version has been built or tested even once. This proposal stays scoped to communication/conversation. If the conversation-specific version gets built and holds up against real use, the domain-general version is the next proposal, earned with evidence, not the current one, expanded on conviction. A rename to something covering "everything Lumin generates" also almost certainly outgrows `docs/LUMIN_DOCTRINE.md` as its home and would need a different constitutional level entirely (North Star SSOT, full Article VII, real review period) — a much higher bar, appropriately deferred until there's something real to point to.
